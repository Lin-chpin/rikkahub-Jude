## 当前工作区

- 普通聊天 AI 语音条：`text_to_speech` 改为一次性结构化回复工具，模型可用 `【语音条】` / `【文本】` 混排完整回复并生成多个语音条；语音段直连当前 TTS Provider 合成、自动保存，气泡点击播放后展开正文并支持普通聊天分段翻译。协议解析、落盘编排、TTS 生成、混排 UI 与单气泡 UI 已按职责拆分；public 定向单测及 public/personal 编译已通过，尚未打包。
- 通话页面已接入普通聊天的消息翻译按钮与翻译模型流程：每个助手气泡内部都有独立按钮，结果显示在同一气泡内的按钮下方，并通过消息 `voiceCallTranslations` 按气泡持久化；通话页固定翻译为简体中文，已有翻译命中缓存，不会重复请求，清除翻译也会写回会话；翻译前后均过滤语音情绪/表演标签，已使用本机 Gradle/JDK 编译并打包 Personal universal debug APK。
- 普通聊天 TTS 引号过滤已拆出独立文本变换层：手动朗读、逐段朗读和自动朗读统一处理 ASCII/中文引号，缓存按实际朗读文本区分；已补单测并通过 public flavor 编译与定向单测。
- TTS 设置页已覆盖逐段朗读、仅引号、仅英文和生成后自动播放；ElevenLabs 语言代码与 MiniMax 语言/方言增强配置已接入 provider 请求边界。

- 语音通话标签改动：已增加关闭/二次标注/模型实时三种模式及通话页状态显示；实时模式的 v3 标签和 MiniMax 2.8 整体情绪提示按请求临时注入，标签进入通话气泡，2.8 情绪按本次 TTS 请求传入。默认二次标注仍保留原流程；OCR/压缩「单独使用模型 API」关闭时默认聊天模型并保留模型选择（复用标题总结模型样式）。
- 语音标签 missing_tool_call 根因：模型注册表按 id 匹配能力，Qwen3-14B / Qwen-2.5-14B-instruct 或从模型列表选择（能力标记为空）的模型匹配不到 TOOL，各 provider 不发送 tools；已在二次标注请求强制携带 TOOL 能力修复。
- 方案 A（通用修复）：四个 provider（OpenAI ChatCompletions / Responses API / Claude / Google）不再按注册表 TOOL 能力标记门控 tools——只要调用方明确传了工具就发送；同时移除基于该标记的"模型未开启工具调用"误报。主聊天搜索/MCP/本地工具与语音标签对未收录 id 的模型全部生效。
- 通话与私有心跳隔离：新增 `VoiceCallSessionRegistry` 作为跨边界协调点；心跳不在活跃通话期间执行或恢复旧排队任务，通话 TTS 的瞬时错误不再自动挂断。
- 私有心跳决策链：已拆出 `HeartbeatDesireState`、`HeartbeatDecisionEngine`、`HeartbeatDeliveryGuard` 和 `HeartbeatPrivateExperienceStore`；下一次唤醒改为状态驱动，发送前会重新检查用户是否已回来，私有候选记录不进入聊天时间线。
- 私有心跳自主闹钟：仅普通聊天可调用 `heartbeat_schedule`，支持指定时间、固定间隔、时间窗随机多次、重复间隔、查询和取消；后台心跳不注入该工具，只执行已保存计划。
- 私有心跳可靠性：已增加结构化失败原因、连续失败诊断、5 分钟起步且最高 6 小时的退避重试、普通调度抖动、损坏状态恢复记录和只读测试；只读测试不消费计划、不执行写工具、不写会话、不发通知、不改正式调度。personal 编译和定向单测已通过。
