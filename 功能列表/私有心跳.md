# 私有心跳

> 私有心跳是 `personal` flavor 专属的本地功能：定时让当前助手在后台生成一条主动消息。源码位于 git 忽略的 `app/src/personal/`，只存在于本机工作区，禁止提交到仓库；公开（public）构建不含任何心跳代码。

## 能力

- 定时心跳：启用后在 `[最短间隔, 最长间隔]` 分钟内随机触发一次（默认 60～180 分钟），模型决定发一条简短自然的主动消息，或回复 `[PASS]` 跳过。
- 主动消息写入当前助手最近会话（无会话则新建），并推送通知，点击通知可跳回对应会话。
- 后台安全边界：构造模型请求前按工具白名单过滤；只读与自主工具直接执行，低风险写入需开关开启，未知/高风险工具不注入请求。
- 可编辑心跳提示词；固定上下文不可被提示词覆盖：每次告知距用户最后一条消息过去了多久（或尚无用户消息）。
- 独立设置页「私有心跳」：启停、间隔/超时/最大工具步数、工具白名单、下次触发时间、运行状态，并支持立即触发。
- 运行状态机：`IDLE / QUEUED / RUNNING / SENT / PASS / SKIPPED_PENDING_USER / SKIPPED_BUSY / SKIPPED_NO_MODEL / SKIPPED_DISABLED / TIMED_OUT / CANCELLED / FAILED`，状态写入 SharedPreferences 供设置页展示。
- 通知：渠道「私有心跳」；运行中显示低优先级常驻通知；生成的主动消息与 `ask_user` 提问均通过通知送达。
- 晚安模式：用户最后一条消息含「晚安」时，心跳改为每 10 分钟触发一次，并使用专用系统提示词检查新增使用、锁定对应软件到第二天白天；连续 3 次无新增使用后自动退出晚安模式，恢复正常心跳。

## 核心入口

- 源码根：`app/src/personal/java/me/rerere/rikkahub/personal/heartbeat/`（git 忽略，禁止提交）。
- 应用启动与设置页接线：`RikkaHubApp.kt`、`ui/pages/setting/SettingPage.kt` 调用 `LocalBuildIntegration`；personal 实现位于 `app/src/personal/.../local/LocalBuildIntegration.kt`，public 为空实现 `app/src/public/.../local/LocalBuildIntegration.kt`。
- 配置与状态：`HeartbeatConfig.kt`、`HeartbeatConfigStore.kt`（SharedPreferences `personal_heartbeat`）。
- 调度：`HeartbeatScheduler.kt`（AlarmManager + 随机间隔）、`HeartbeatAlarmReceiver`、`HeartbeatBootReceiver`。
- 执行：`HeartbeatForegroundService.kt`（`specialUse` 前台服务）、`HeartbeatGenerationWorkflow.kt`、`HeartbeatToolPolicy.kt`。
- 提示词与通知：`HeartbeatPromptContext.kt`、`HeartbeatNotifications.kt`。
- 设置 UI 与文案：`HeartbeatSettingsActivity.kt`、`app/src/personal/res/values/strings.xml`。
- 清单：`app/src/personal/AndroidManifest.xml`（`SCHEDULE_EXACT_ALARM`、Activity、Service、两个 Receiver）。

## 运行与数据

- 配置存 SharedPreferences（`personal_heartbeat`），不是 DataStore/Room：`config`（JSON）、`next_trigger_at`、`last_claim_at`、`run_phase`、`run_detail`、`run_updated_at`。
- 调度：优先 `setExactAndAllowWhileIdle`，Android 12+ 无精确闹钟权限时回退 `setAndAllowWhileIdle`；开机与覆盖安装后重新同步；过期触发按用户消息锚点重新计算，不会因打开应用而立即触发。
- 调度双保险：启用后由 `HeartbeatForegroundService` 以 `START_STICKY` 常驻前台，并在服务内部检查下次触发时间；AlarmManager 作为进程被系统杀死后的冷启动兜底。后台执行不再依赖普通 Application 协程去启动新的前台服务。
- 用户消息锚点：下次触发不早于「最后一条用户消息 + 随机间隔」，用户刚聊完天不会被立刻打扰；晚安模式仍固定 10 分钟。
- 用户活动入口：`HeartbeatUserActivity.kt` 在消息持久化后立即记录消息时间和「晚安」状态；前台服务启动时可恢复 `QUEUED` 触发，避免闹钟已入队但服务尚未执行时丢失。
- 触发保护：进程内互斥 + 最小间隔（`lastClaimAt`）；「立即触发」跳过最小间隔但仍受互斥保护；会话正在生成时跳过（`SKIPPED_BUSY`）。
- 生成流程：取配置助手（缺省当前助手）→ 解析模型（助手/全局聊天模型，无模型则 `SKIPPED_NO_MODEL`）→ 最近会话历史（过滤未完成的工具消息、按 `contextMessageSize` 截取）→ 上一条是用户消息则跳过（`SKIPPED_PENDING_USER`）→ 生成（本地工具/MCP/记忆，`maxToolSteps` 步内、`generationTimeoutSeconds` 超时）→ `[PASS]` 或空文本则 `PASS`，否则写入会话并通知。
- 工具策略：`readOnlyToolNames` 与 `autonomousToolNames` 直接执行；`lowRiskWriteToolNames` 需开启允许低风险写入；其余工具不注入。`ask_user` 改为通知提问、无需审批。
- 晚安模式状态存 SharedPreferences：`good_night_active`、`good_night_no_usage_runs`。模式开启时调度固定 10 分钟；每次运行检测是否执行了 `usage_lock_control` 的 `action=lock`，有则清零计数，无则累计，满 3 次退出模式；用户重新发言（非晚安）也会退出。

## 构建边界

- `app/build.gradle.kts` 定义 `distribution` 维度 flavor：`public` / `personal`。
- 公开包：`scripts\build-universal-debug-apk.ps1` 执行 `:app:assemblePublicDebug`，输出 `app/build/outputs/apk/public/debug/app-public-universal-debug.apk`，不含心跳。
- 私有包：`scripts\personal\build-personal-universal-debug-apk.ps1` 执行 `:app:assemblePersonalDebug`，输出 `app/build/outputs/apk/personal/debug/app-personal-universal-debug.apk` 及时间戳副本，并用 `scripts\personal\verify-build-boundary.ps1` 校验私有包包含心跳、公开包不含心跳。
- `.gitignore` 忽略 `/app/src/personal/`、`/app/src/testPersonal/`、`/app/src/androidTestPersonal/`、`/scripts/personal/`、`/personal.properties`；用户明确禁止提交心跳相关内容。
