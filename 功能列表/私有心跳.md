# 私有心跳

> 私有心跳是 `personal` flavor 专属的本地功能：定时让当前助手在后台生成一条主动消息。源码位于 git 忽略的 `app/src/personal/`，只存在于本机工作区，禁止提交到仓库；公开（public）构建不含任何心跳代码。

## 能力

- 定时心跳：启用后在 `[最短间隔, 最长间隔]` 分钟范围内根据时间驱动的念头压力计算下一次唤醒，模型决定发一条简短自然的主动消息，或回复 `[PASS]` 跳过。
- 自主闹钟：只有普通聊天可调用 `heartbeat_schedule`，由 AI 指定下一次时间、固定间隔、某个时间窗内随机多次唤醒，或取消/查看计划；私有心跳只执行已保存计划，不注入该工具，避免后台改写计划与聊天窗口冲突。
- 主动消息写入当前助手最近会话（无会话则新建），并推送通知，点击通知可跳回对应会话。
- 后台安全边界：构造模型请求前按工具白名单过滤；只读与自主工具直接执行，低风险写入需开关开启，未知/高风险工具不注入请求。
- 可编辑心跳提示词；固定上下文不可被提示词覆盖：每次告知距用户最后一条消息过去了多久（或尚无用户消息）。
- 独立设置页「私有心跳」：启停、间隔/超时/最大工具步数、工具白名单、下次触发时间、运行状态，并支持立即触发和只读测试。只读测试会真实请求模型，但只注入只读白名单工具，不消费自主计划、不写会话、不发通知，也不改变正式调度。
- 运行状态机：`IDLE / QUEUED / RUNNING / SENT / PASS / SKIPPED_PENDING_USER / SKIPPED_BUSY / SKIPPED_NO_MODEL / SKIPPED_DISABLED / TIMED_OUT / CANCELLED / FAILED / TESTED`。状态同时记录稳定原因码、触发来源、耗时和安全截断后的详情，设置页按网络、鉴权、限流、超时、存储、工具、服务启动、模型配置和普通生成错误分别说明。
- 运行诊断：设置页展示最近成功、最近失败及原因、连续失败次数、下次重试、最近耗时和损坏状态恢复记录；配置超出合法范围时在保存前提示，不再静默修正。
- 通知：渠道「私有心跳」；服务常驻时显示等待下一次触发，真正取得执行权并发起模型请求时才显示“正在生成”；生成的主动消息与 `ask_user` 提问均通过通知送达。执行异常、超时或取消都会记录状态、释放互斥并重新安排下一次触发。
- 晚安模式：用户最后一条消息含「晚安」时，心跳改为每 10 分钟触发一次，并使用专用系统提示词检查新增使用、锁定对应软件到第二天白天；连续 3 次无新增使用后自动退出晚安模式，恢复正常心跳。
- 内部念头与对话分离：心跳生成的候选文本、压力、评分、跳过原因写入独立的私有体验记录；只有真正写入会话的主动消息才进入重复检测历史。

## 运行与数据

- 配置存 SharedPreferences（`personal_heartbeat`），不是 DataStore/Room：配置、念头状态、下次触发、执行占用、结构化运行状态和带 schema 版本的诊断记录均独立持久化；配置、念头或诊断 JSON 损坏时删除损坏项、恢复安全默认值并留下恢复记录。私有体验记录独立存放在 `personal_heartbeat_experience`。
- 调度：优先 `setExactAndAllowWhileIdle`，Android 12+ 无精确闹钟权限时回退 `setAndAllowWhileIdle`；开机与覆盖安装后重新同步；过期触发按用户消息锚点重新计算，不会因打开应用而立即触发。
- 调度双保险：启用后由 `HeartbeatForegroundService` 以 `START_STICKY` 常驻前台，并在服务内部检查下次触发时间；AlarmManager 作为进程被系统杀死后的冷启动兜底。后台执行不再依赖普通 Application 协程去启动新的前台服务。
- 用户消息锚点：普通调度加入边界内小幅随机抖动；下次触发同时不早于「最后一条用户消息 + 间隔」和「本次重新调度时间 + 间隔」，避免用户刚聊完或一次心跳结束后立刻重复触发；晚安模式仍固定 10 分钟。
- 自主计划：`heartbeat_schedule` 写入独立 SharedPreferences；计划存在时调度器优先使用计划时间，不套用普通心跳的最短间隔，执行到期项后再安排下一项或恢复默认状态驱动调度。
- 用户活动入口：`HeartbeatUserActivity.kt` 在消息持久化后立即记录消息时间和「晚安」状态；前台服务启动时可恢复 `QUEUED` 触发，避免闹钟已入队但服务尚未执行时丢失。
- 触发保护：进程内互斥 + 最小间隔（`lastClaimAt`）；「立即触发」跳过最小间隔但仍受互斥保护；会话正在生成时安全跳过。网络、鉴权、限流、模型、存储、工具或服务错误才计入连续失败，并按 5 分钟起步、最高 6 小时的指数退避和小幅抖动重试；用户回来、通话中或会话忙不误记为基础设施失败。
- 失败关闭：无法确认模型、上下文、工具或投递状态安全时不写消息；失败重试可绕过普通最短心跳间隔，但不会绕过进程互斥、通话保护和投递前守卫。成功发送或正常 `PASS` 后清零连续失败并恢复普通调度。
- 投递前守卫：模型生成完成后再次检查通话状态、会话生成状态和用户消息时间；用户在心跳思考期间回来时不写入主动消息。
- 通话保护：通话 UI 通过 `VoiceCallSessionRegistry` 注册活跃会话；心跳服务在启动、恢复旧 `QUEUED` 运行和生成前检查该边界，通话期间跳过并重新安排下一次触发。
- `QUEUED` 恢复仅在没有下一次闹钟或闹钟已经到期时执行，避免应用打开时恢复带有未来闹钟的旧排队状态。
- 生成流程：取配置助手或自主计划指定的助手（无模型则 `SKIPPED_NO_MODEL`）→ 最近会话历史（过滤未完成的工具消息、按 `contextMessageSize` 截取）→ 上一条是用户消息则跳过（`SKIPPED_PENDING_USER`）→ 生成（本地工具/MCP/记忆，`maxToolSteps` 步内、`generationTimeoutSeconds` 超时；不注入 `heartbeat_schedule`）→ `[PASS]` 或空文本则 `PASS` → `HeartbeatDecisionEngine` 做中文可用的重复检测和评分 → 投递前守卫通过后写入会话并通知。
- 工具策略：`readOnlyToolNames` 与 `autonomousToolNames` 直接执行；`lowRiskWriteToolNames` 需开启允许低风险写入；其余工具不注入。`ask_user` 改为通知提问、无需审批。
- 晚安模式状态存 SharedPreferences：`good_night_active`、`good_night_no_usage_runs`。模式开启时调度固定 10 分钟；每次运行检测是否执行了 `usage_lock_control` 的 `action=lock`，有则清零计数，无则累计，满 3 次退出模式；用户重新发言（非晚安）也会退出。

## 构建边界

- `app/build.gradle.kts` 定义 `distribution` 维度 flavor：`public` / `personal`。
- 公开包：`scripts\build-universal-debug-apk.ps1` 执行 `:app:assemblePublicDebug`，输出 `app/build/outputs/apk/public/debug/app-public-universal-debug.apk`，不含心跳。
- 私有包：`scripts\personal\build-personal-universal-debug-apk.ps1` 执行 `:app:assemblePersonalDebug`，输出 `app/build/outputs/apk/personal/debug/app-personal-universal-debug.apk` 及时间戳副本，并用 `scripts\personal\verify-build-boundary.ps1` 校验私有包包含心跳、公开包不含心跳。
- `.gitignore` 忽略 `/app/src/personal/`、`/app/src/testPersonal/`、`/app/src/androidTestPersonal/`、`/scripts/personal/`、`/personal.properties`；用户明确禁止提交心跳相关内容。
