# 语音与多媒体

## 能力

- TTS 多供应商、ElevenLabs v3、MiniMax Speech 2.6/2.8、段落朗读、自动播放、仅引用/仅英文等策略；MiniMax Speech 2.6 支持全局情绪参数，MiniMax Speech 2.8 的通话实时模式也支持按回复临时传入情绪。
- 普通聊天的 TTS 设置包括显示逐段朗读按钮、仅朗读引号内容、仅朗读英文和生成后自动播放；手动朗读、逐段朗读与自动朗读共用文本变换逻辑，支持中英文及中文排版引号，已保存音频按实际朗读文本缓存。
- 助手启用「AI 语音条」本地工具后，可先调用一次 `text_to_speech` 进入结构化回复模式，再用 `【语音条】` / `【文本】` 输出完整混排回复；一次调用可产生任意数量和顺序的语音条与普通文本。语音段直接使用当前 TTS Provider 合成并保存，不进入通话二次情绪标签或实时标签链路；语音气泡默认折叠正文，点击播放后展开，并按普通聊天翻译模型和语言选择流程逐条翻译。
- 通话气泡复用普通聊天的翻译按钮、翻译模型和清除翻译流程；每个助手气泡内部都有独立翻译按钮，结果显示在同一气泡内的按钮下方并按气泡单独缓存。通话页点击后固定翻译为简体中文，翻译前后均清除语音情绪/表演标签。
- ElevenLabs 支持可选语言代码；MiniMax 支持可选语言/方言增强参数，均只在对应 provider 配置和请求边界生效。
- ASR 提供商和系统输入法语音通话界面。
- 助手可在启用本地工具后主动邀请当前聊天用户通话；来电支持震动、滑动接听、拒接和 30 秒未接反馈。接听后明确回传 `ACTIVE` 状态；接通后的首条用户语音请求副本也会携带一次 `ACTIVE` 用户消息内事件。成功且存在有效对话的挂断会更新原工具结果，并在独立通话记录节点保存一个待消费的 `ENDED` 事件。
- 无论通话由用户还是助手发起，接通后的用户首句及后续发言都以 `VoiceCall` 模式请求模型，并在 system 消息末尾注入 `ACTIVE` 运行时状态；只有首句额外在用户消息请求副本中携带 `ACTIVE` 事件，状态同时要求模型自行将完整回复收束在 200 字以内，客户端不做硬截断。挂断不立即请求 API；下一条普通用户消息请求副本携带 `ENDED` system 状态和用户消息内事件，消费后后续普通聊天使用 `INACTIVE`。
- 通话标签有「关闭标签」「二次情绪标签」「模型实时标签」三种模式，设置页可切换，通话页显示当前模式。默认仍是两阶段生成：第一次按正常通话规则生成回复；客户端持有原文并按句分段，第二次调用只保留独立标签协议和声音导演人设，输入只包含带索引的原文分段。模型实时模式把临时标签提示附加到每条送入模型的用户消息副本：ElevenLabs v3 直接生成方括号标签；MiniMax Speech 2.8 生成首行整体情绪标记，客户端在 TTS 请求中传入情绪并在送语音前移除控制标记。实时模式的标签/情绪标记会进入通话气泡，便于测试；二次模式也在通话气泡显示最终语音副本中的标签。
- 图片、PDF、DOCX、PPTX、EPUB 等多模态输入；OCR 可使用独立接口。
- 图片生成、文件预览、本地图片持久化和 Markdown/代码/公式渲染。

- 二次语音情绪标签模型默认跟随当前聊天模型，也可在设置的默认模型和提示词页面通过「单独使用模型 API」开关选择独立 API 与模型；关闭时保留模型选择按钮（复用标题总结模型样式，默认显示聊天模型，可换模型，清除后回到聊天模型），未配置聊天模型时直接报错。
- 二次标注请求会强制给模型加上 TOOL 能力标记：模型注册表按 id 匹配能力，`Qwen3-14B`、`Qwen-2.5-14B-instruct` 这类常见 id（或从模型列表选择、能力标记为空）匹配不到 TOOL，导致各 provider 不发送 tools、模型只能回文本而触发 `missing_tool_call` 回退；强制标记后工具定义一定会发给 API。

## 修改提示

- 通话状态只在 `VoiceCallRuntimePrompt.kt` 修改：双方任一方发起并接通后都使用 `ACTIVE`，首条用户语音的请求副本额外携带一次 `ACTIVE` 事件；挂断后的下一条普通用户请求同时发送 `ENDED` system 状态和用户消息内事件，并禁用再次拨号；事件消费后普通文字请求使用 `INACTIVE`。
- `VoiceCallConversationPresentation.kt` 只改变普通聊天展示，不删除原始通话消息；记录页继续用原消息和已保存音频回放。
- 键盘关闭与挂断是不同生命周期事件，修改通话 Dialog 时不可混用。
- 主动来电复用工具审批状态；接听后以 `VoiceCall` 模式续跑，拒接或超时结果必须返回模型。
- 接听和挂断仍会更新同一工具调用的状态；仅成功且存在有效对话的挂断会留下待消费事件，不主动生成告别回复。下一条普通用户消息消费事件时，模型必须按非通话状态回复，且不能输出音频标签、情绪标签或自行重新拨号。
- 二次标注模式的结构化标签只在已接通通话中注入；原始工具参数不进入消息文本，客户端生成的合法标签保存在通用消息元数据中，供 TTS 和通话界面核验使用。模型实时模式的标签是本次请求直接生成的可见文本，不走二次标注元数据。继续兼容读取旧的 `elevenLabsV3VoiceCall` 元数据。
- 第二次标注模式关闭记忆、普通工具、技能、推理和模型流式输出，只临时注入 `select_voice_call_audio_tags` 专用工具。工具参数的 `tagId` 是共用标签目录生成的 JSON Schema 枚举，并再次校验分段数量、索引完整性和标签合法性；模型不能提供正文。供应商格式化在校验后进行：ElevenLabs v3 使用 `[word]`，MiniMax Speech 2.8 使用 `(word)`。模型实时模式不走第二次标注请求，提示词和用户消息副本在本次请求结束后即失效。
- 二次请求异常、未调用专用工具或工具参数无效时，ElevenLabs v3 使用 `breath` 回退，MiniMax Speech 2.8 使用无标签回退；只读英文模式下回退也只作用于英文分段，不会给中文加标签。通话 UI 显示 `request_error`、`missing_tool_call` 或 `invalid_tool_arguments`。
- 普通聊天展示和送模上下文都必须清除已知方括号、圆括号通话标签及标签元数据，避免挂断后的文本聊天继续模仿通话输出。
- 多媒体 URI 写入持久化数据前要复制到应用私有目录。
- OCR/压缩独立 API 配置不能污染普通聊天供应商设置。
- MiniMax Speech 2.8 没有句首语气词时也会尽量为每个分段选择一个合适的声音标签；replacementText 仅在存在可替换的句首语气词时填写，NONE 只作为确实不适合声音事件时的兜底。
- 通话结束后若 AI 有说话内容，生成一张内容自适应宽度的通话记录卡片，宽度行为与折叠的纯思考链气泡一致；通话页和记录页的 AI 气泡均可播放通话期间保存的 TTS 音频，不重新合成。长按记录卡片会弹出“是否删除”确认框，确认后删除该次通话的原始用户/AI消息、独立记录节点和保存的音频文件，取消则不做修改。
- 通话记录卡片作为会话末尾唯一的独立消息节点保存，并在该节点内持有通话消息 ID 与分消息音频映射；原始对话消息不再挂载通话记录注解。记录节点不参与后续模型上下文或自动播放，旧版挂载式记录继续兼容读取和删除。
- MiniMax 全部模型（2.6/2.8）在通话中按句切片、逐句合成并逐句播放，气泡文本随当前朗读句同步显示；整段合成只保留给 ElevenLabs v3。
- 通话期间通过独立的进程内会话注册边界阻止私有心跳启动或恢复，TTS 瞬时不可用/播放失败只提示错误，不自动挂断当前通话。
